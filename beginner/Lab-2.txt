# Lab 2: Das nRF93M1 DK online bringen

Einsteiger-Workshop · 45 Minuten · Trainerleitfaden mit Teilnehmerübung

Lernziel: Am Ende dieses Labs können alle Teilnehmenden den Mobilfunkstatus ihres nRF93M1 DK prüfen, die Geräte-ID auslesen, das Gerät für nRF Cloud registrieren und die Voraussetzungen für eine Cloud-Verbindung überprüfen.

Wichtig ist die Trennung zwischen drei Schritten:

1. Modem ansprechen: Funktioniert die serielle AT-Schnittstelle?
2. Mobilfunk herstellen: Ist das Modem im LTE-Netz registriert?
3. Cloud-Provisionierung: Ist das Gerät in nRF Cloud bekannt und für die Kommunikation eingerichtet?

Eine erfolgreiche AT-Antwort allein bedeutet noch nicht, dass LTE oder die Cloud funktionieren.

## 3. Übung A – LTE-Registrierung prüfen (Minuten 0–15)

### Schritt 1: Modem ansprechen

Im seriellen Terminal:

```
AT
```

Erwartete Antwort:

```
OK
```

Dann die Fehlerausgaben aktivieren und Firmwareversion prüfen:

```
AT+CMEE=2
AT+CGMR
AT+CLAC
```

Erwartung:

- `AT+CMEE=2` liefert `OK`.
- `AT+CGMR` liefert eine Firmwareversion.
- `AT+CLAC` listet die unterstützten AT-Kommandos auf.

### Schritt 2: Modem aktivieren

```
AT+CFUN=1
```

Erwartete Antwort:

```
OK
```

Das Modem kann anschließend etwas Zeit benötigen, um das Mobilfunknetz zu finden und sich zu registrieren. Nicht unmittelbar nach dem `OK` von `AT+CFUN=1` davon ausgehen, dass die Registrierung bereits abgeschlossen ist. Nordic beschreibt diesen Befehl als Teil der grundlegenden Modem-Inbetriebnahme.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://nrfconnectdocs.nordicsemi.com\&sz=32)

nRF Connect SDK 3.4.99 documentation



### Schritt 3: Registrierungsstatus abfragen

```
AT+CEREG?
```

Eine beispielhafte Antwort:

```
+CEREG: 1,1,"1A2B","01234567",7
OK
```

Entscheidend ist der zweite Zahlenwert nach `+CEREG:`:

| Zweiter Wert | Bedeutung                             |
| ------------ | ------------------------------------- |
| `1`          | Im Heimnetz registriert               |
| `5`          | Im Roaming-Netz registriert           |
| `0`          | Nicht registriert, keine aktive Suche |
| `2`          | Suche nach einem Netz läuft           |
| `3`          | Registrierung abgelehnt               |

Die Beispielwerte für Zellkennung und weitere Felder sind nicht fest; sie hängen vom Netz und Modemstatus ab. Laut Nordic zeigen `1` und `5` an dieser Position eine erfolgreiche Registrierung an.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://nrfconnectdocs.nordicsemi.com\&sz=32)

nRF Connect SDK 3.4.99 documentation



Erfolgskriterium für diesen Abschnitt: Die Teilnehmenden können erklären, ob das Modem im LTE-Netz registriert ist. Falls nicht, dokumentieren sie den Status und gehen in die Fehlersuche, statt einfach fortzufahren.

## 4. Übung B – Geräteidentität und Registrierungs-Token abrufen (Minuten 15–25)

Das Ziel ist, die Geräteidentität und ein für das Onboarding benötigtes Token auszulesen.

### Schritt 1: UUID auslesen

```
AT%DEVICEUUID
```

Beispielausgabe:

```
%DEVICEUUID: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
OK
```

Die UUID ist eine stabile Gerätekennung. Die Zeichenfolge oben ist nur ein Platzhalter – jede Person muss die UUID des eigenen Boards verwenden.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://nrfconnectdocs.nordicsemi.com\&sz=32)

nRF Connect SDK 3.4.99 documentation



### Schritt 2: Team-ID in nRF Cloud finden

1. In nRF Cloud anmelden: [nRF Cloud öffnen](https://nrfcloud.com/?utm_source=chatgpt.com).
2. Unten links die Legacy App öffnen.
3. Das Menü oben rechts öffnen.
4. Team auswählen.
5. Die angezeigte Team ID notieren.
6. Über NEW EXPERIENCE zurück zur neuen nRF-Cloud-Oberfläche wechseln.

Die Bezeichnungen und Positionen in der Benutzeroberfläche können sich mit Updates ändern; im Zweifelsfall die aktuelle Nordic-Anleitung verwenden.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://nrfconnectdocs.nordicsemi.com\&sz=32)

nRF Connect SDK 3.4.99 documentation



### Schritt 3: Registration JWT anfordern

Die eigene Team-ID in das Kommando einsetzen:

```
AT%REGJWT="<TEAM-ID>"
```

Beispiel einer schematischen Antwort:

```
%REGJWT: xxxxx.xxxxx.xxxxx
OK
```

Wichtig: `<TEAM-ID>` einschließlich der spitzen Klammern ist ein Platzhalter und darf nicht wörtlich eingegeben werden. Die Anführungszeichen um die echte Team-ID bleiben erhalten.

Beide Werte – UUID und Registration JWT – werden gleich im Cloud-Portal benötigt.

Sicherheitshinweis

Das Registration JWT wie ein Zugangstoken behandeln: nicht auf einem gemeinsamen Beamer zeigen, nicht in öffentliche Kurs-Chats kopieren und nach dem Workshop nicht in gemeinsam genutzten Logs ablegen. Nur im eigenen nRF-Cloud-Onboarding verwenden.

Nordic weist außerdem darauf hin, dass die Gerätezeit gültig sein muss, damit JWTs akzeptiert werden. Falls die Anmeldung später mit einem Authentifizierungsfehler scheitert, ist die Systemzeit ein früher Prüfpunkt.&#x20;

## 6. Troubleshooting – typische Fehlerbilder (Minuten 35–45)

Diese Tabelle eignet sich als Arbeitsblatt: Die Teilnehmenden sollen zuerst selbst eine Ursache nennen und dann den nächsten sinnvollen Prüfschritt auswählen.

| Symptom                                                              | Wahrscheinliche Ursache                                                  | Nächster Prüfschritt                                            |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------ | --------------------------------------------------------------- |
| Keine Antwort auf `AT`                                               | Falscher Port, falsche Baudrate, Modem nicht bereit                      | USB-Verbindung und seriellen Port prüfen                        |
| `AT` funktioniert, aber `CEREG` zeigt `0` oder `2`                   | Noch keine Registrierung oder Netzsuche läuft                            | Antenne, SIM, Abdeckung und Tarif prüfen; erneut abfragen       |
| `CEREG` zeigt `3`                                                    | Registrierung abgelehnt                                                  | SIM-/Netzbetreiberfreigabe, Tarif und Netzkompatibilität prüfen |
| `AT%DEVICEUUID` liefert `ERROR`                                      | Kommando nicht verfügbar oder nicht von dieser Firmware unterstützt      | `AT+CGMR`, `AT+CLAC` und Firmware-Kompatibilität prüfen         |
| `AT%REGJWT` schlägt fehl                                             | Team-ID falsch, Token-Erzeugung fehlgeschlagen oder Systemzeit ungültig  | Team-ID und Zeitbasis kontrollieren                             |
| Gerät erscheint nicht in Fleet                                       | Onboarding nicht abgeschlossen, falsche Daten oder Berechtigungsproblem  | UUID und JWT erneut prüfen; Eingabe und Account kontrollieren   |
| Gerät erscheint in Fleet, aber es kommen später keine Nachrichten an | Provisionierung allein bestätigt noch keinen erfolgreichen Datentransfer | LTE-Status und Cloud-Transaktion im nächsten Lab testen         |

Die genaue Verfügbarkeit von AT-Kommandos und Parametern ist firmwareabhängig. Nordic empfiehlt, die Version mit `AT+CGMR` zu erfassen und die unterstützten Kommandos über `AT+CLAC` zu prüfen.&#x20;

### Mini-Challenge für die Gruppe

Szenario: Das Terminal antwortet auf `AT` mit `OK`. `AT+CEREG?` liefert aber `+CEREG: 0,2`. Was wisst ihr bereits – und was noch nicht?

Das Modem ist vollständig mit nRF Cloud verbunden.

Die serielle Kommunikation funktioniert; die LTE-Registrierung ist noch nicht abgeschlossen.

Die SIM-Karte ist definitiv defekt.
